# راه‌اندازی Loomi برای مالک — از سرور خالی تا ورود تسترها

این سند مسیر عملی است: یک سرور Linux خالی، تا جایی که تسترها می‌توانند وارد شوند و تصویر بسازند. برای معماری و تصمیم‌های طراحی به `docs/ARCHITECTURE.md` و برای جزئیات کامل API به `docs/API.md` مراجعه کنید؛ اینجا فقط عملیات است.

## پیش‌نیازها

- یک سرور Linux (x86_64) با **Docker Engine** و پلاگین **Docker Compose v2** نصب‌شده (`docker compose version`).
- یک **دامنه** که از قبل با رکورد A/AAAA به IP همین سرور اشاره می‌کند — برای HTTPS خودکار (Caddy) یا برای گواهی certbot (nginx) لازم است.
- **RAM** بر اساس تعداد حساب ChatGPT هم‌زمانی که می‌خواهید وصل کنید؛ جدول کامل در `README.md` («اندازه سرور برای چند حساب هم‌زمان») است، خلاصه‌اش:

  | حساب‌های متصل هم‌زمان | حافظه کانتینر (کف) |
  |---|---|
  | ۱ | ~۱ گیگابایت |
  | ۲ | ~۱.۵ گیگابایت |
  | ۴ | ~۲.۵ گیگابایت |

- پورت‌های ۸۰ و ۴۴۳ باز و آزاد باشند (برای هرکدام از دو روش HTTPS پایین).

## ۱. دریافت کد و آماده‌سازی `.env`

```bash
git clone <آدرس مخزن> loomi && cd loomi
bash deploy/setup.sh loomi.example.com
```

`deploy/setup.sh`:

- اگر `.env` وجود نداشته باشد، از `.env.example` می‌سازد.
- یک `LOOMI_ACCESS_KEY` تصادفی و قوی (۶۴ نویسه هگز) می‌سازد و در `.env` می‌نویسد — **هرگز آن را روی صفحه چاپ نمی‌کند** و اگر کلیدی از قبل باشد دست نمی‌زند، پس اجرای دوباره‌اش امن است.
- `LOOMI_HOSTS` و `LOOMI_DOMAIN` را از دامنه‌ای که می‌دهید تنظیم می‌کند. بدون آرگومان و در یک ترمینال واقعی، خودش دامنه را می‌پرسد.

خودتان `.env` را باز کنید و کلید را همان‌جا بخوانید (لازم می‌شود، پایین را ببینید). کامنت بالای `LOOMI_PROXY_IP` در `.env.example` می‌گوید کدام مقدار را بگذارید — به اینکه کدام روش HTTPS را در قدم بعد انتخاب می‌کنید بستگی دارد.

## ۲. بالا آوردن با HTTPS خودکار (پیشنهادی — Caddy)

```bash
docker compose --profile caddy up -d --build
```

`deploy/Caddyfile` گواهی Let's Encrypt/ZeroSSL را خودش برای `LOOMI_DOMAIN` می‌گیرد و تازه نگه می‌دارد، روی ۸۰ و ۴۴۳ گوش می‌دهد، و به‌صورت شفاف به noVNC (مسیر `/desktop/`) و SignalR (مسیر `/hubs/`) هم بدون هیچ تنظیم اضافه‌ای WebSocket را عبور می‌دهد. خود Loomi فقط روی `127.0.0.1:5080` در دسترس است، هرگز مستقیم بیرون.

اگر این روش را انتخاب کردید، در `.env`:

```
LOOMI_PROXY_IP=172.28.0.9
```

(همان IP ثابتی که Caddy در شبکه Compose دارد؛ توضیح کامل در کامنت‌های `docker-compose.yml`.)

## یا: nginx که خودتان مدیریت می‌کنید

اگر روی همین سرور nginx/certbot دیگری هم دارید و ترجیح می‌دهید پراکسی را خودتان مدیریت کنید، پروفایل Caddy را اجرا نکنید:

```bash
docker compose up -d --build
```

`deploy/nginx.conf` یک نمونه‌ی کامل (HTTPS، WebSocket، `client_max_body_size`) است؛ دامنه و مسیر گواهی را در آن عوض کنید و به تنظیمات nginx خودتان اضافه کنید. در این حالت در `.env`:

```
LOOMI_PROXY_IP=172.17.0.1
```

(gateway پیش‌فرض bridge داکر؛ اگر شبکه‌تان فرق دارد مقدارش را بررسی کنید — توضیح کامل در `.env.example`.)

**این دو روش را با هم اجرا نکنید.**

## ۳. اولین بالاآمدن

```bash
docker compose ps
docker compose logs -f loomi
```

دنبال healthcheck سبز و بدون خطا در لاگ باشید (migration پایگاه‌داده خودش در استارتاپ اجرا می‌شود). بعد به آدرس دامنه‌تان بروید.

## ۴. اولین ورود مالک

نام‌کاربری **owner** و رمز همان **`LOOMI_ACCESS_KEY`** که در `.env` نوشته شده است (همان‌جا بخوانیدش؛ هیچ اسکریپتی آن را دوباره چاپ نمی‌کند). بعد از ورود، از Settings می‌توانید همین رمز را هم عوض کنید.

## ۵. اتصال یک حساب ChatGPT

1. Settings → **Provider accounts** → **Add account**: یک نام بدهید، Provider را ChatGPT بگذارید (برای Gemini، به‌جای این مرحله یک کلید API واردکنید — بدون مرورگر).
2. روی **Connect** بزنید، سپس **Open secure browser**. این لینک به `/desktop/` می‌رود که فقط برای owner باز می‌شود — عضوهای عادی حتی این دکمه را نمی‌بینند.
3. داخل همان noVNC، **خودتان دستی** با حساب ChatGPT خودتان وارد شوید؛ هر تأیید دومرحله‌ای هم همان‌جا رفع می‌شود. Loomi خودش رمز یا کد ورود کسی را وارد نمی‌کند و ذخیره‌اش هم نمی‌کند.
4. به Loomi برگردید؛ وضعیت هر چند ثانیه خودکار به‌روزرسانی می‌شود، یا **Check connection** را بزنید. **Connected** یعنی آماده‌ی ساخت تصویر است.

## ۶. ساخت حساب‌های تستر با اعتبار و سهمیه روزانه

Settings → **Users** → **Add user**:

- نام‌کاربری و یک **رمز اول** — همین را به تستر می‌دهید؛ او می‌تواند بعداً خودش عوضش کند (`docs/TESTERS.md`).
- **سهمیه روزانه** (Daily quota): سقف تعداد ساخت تصویر در روز برای آن نفر؛ `۰` یعنی بدون سقف.
- **اعتبار** (Credits) اولیه: موجودی که هر ساخت/ویرایش/شاخه از آن کم می‌شود.

سهمیه روزانه و اعتبار دو محدودیت جدا و مستقل‌اند؛ هرکدام می‌توانند زودتر از دیگری کاربر را متوقف کنند.

## ۷. قیمت‌گذاری

Settings → **Prices**: هزینه‌ی هر تولید را بر اساس Provider (ChatGPT/Gemini) تنظیم می‌کنید، و اختیاری هم بر اساس نوع عملیات (Generate/Edit/Branch) — قیمت مخصوص یک عملیات بر پیش‌فرض همان ارائه‌دهنده اولویت دارد. خانه‌ای را خالی بگذارید تا فقط پیش‌فرض اعمال شود.

## ۸. تحویل اعتبار به تستر

نام‌کاربری و رمز اول را از یک کانال امن (پیام مستقیم، نه ایمیل عمومی یا چت باز) بدهید، و لینک `docs/TESTERS.md` را همراهش بفرستید. از او بخواهید همان بار اول از Settings رمز را عوض کند.

## ۹. پشتیبان‌گیری

```bash
bash deploy/backup.sh
```

بدون متوقف‌کردن سرویس، یک عکس فوری سازگار از پایگاه‌داده (با دستور `.backup` خود SQLite، نه کپی مستقیم فایل زنده)، کلیدهای Data Protection، و تمام تصویرهای تولید/بارگذاری‌شده را در یک `.tar.gz` با برچسب زمان جمع می‌کند؛ دستور بازیابی هم داخل خودش (`RESTORE.md`) است. پروفایل‌های مرورگر (نشست ورود هر حساب ChatGPT) عمداً در این بایگانی نیست — حجیم‌ترین volume است و بازسازی‌اش با یک ورود دستی دوباره همان‌قدر سریع است که بازیابی‌اش از یک نسخه قدیمی، با این ریسک کمتر که به ChatGPT نشستی کهنه تحویل نمی‌دهد. بایگانی را جای دیگری، نه روی همین سرور، نگه دارید.

## ۱۰. به‌روزرسانی

```bash
git pull
docker compose --profile caddy up -d --build   # یا بدون --profile caddy اگر nginx خودتان را دارید
docker compose logs -f loomi
```

پیش از هر ارتقا backup بگیرید. Migration پایگاه‌داده در استارتاپ خودکار اجرا می‌شود؛ لاگ راه‌اندازی را ببینید تا مطمئن شوید بدون خطا بالا آمده. پروفایل‌های مرورگر موجود دست‌نخورده می‌مانند.

بعد از هر ری‌استارت لازم نیست دستی **Connect** بزنید: Loomi هنگام بالا آمدن همه‌ی حساب‌های فعال را خودش وصل می‌کند و چند ثانیه بعد وضعیت Connected می‌شود. اگر نشد، همان حساب از قبل نیاز به ورود داشته است (بخش بعد).

## روی Harbora

نسخه‌ای که روی `https://loomi.platform.irnetfree.info` اجراست همین‌طور بالا آمده است. HTTPS، دامنه و ری‌استارت را خود Harbora می‌دهد؛ Caddy، nginx و `docker compose` لازم نیست.

**یک بار، در پنل:**

1. پروژه‌ی **Loomi** و داخلش اپ **`loomi`**: Source = **Harbora CLI** (Upload)، Container port = **`8080`**، Instance size = **Medium** (۲ گیگ؛ هر حساب ChatGPT یک Chromium حدود ۵۰۰ مگ است).
2. **Volumes** → `/data`. پایگاه‌داده، تصویرها، پروفایل‌های مرورگر و کلیدها همه زیر همین‌اند. نامش روی سرور `harbora-vol-loomi-data` است.
3. **Environment Variables**:
   - `AllowedHosts` = `loomi.platform.irnetfree.info`
   - `Security__KnownNetworks__0` = `10.0.0.0/8`، `Security__KnownNetworks__1` = `172.16.0.0/12`، `Security__KnownNetworks__2` = `192.168.0.0/16` — Traefik بعد از هر ری‌استارت با IP تازه‌ای به شبکه‌ی اپ وصل می‌شود، پس فقط با بازه می‌شود به آن اعتماد کرد. بدون این، همه‌ی تسترها از نگاه Loomi یک IP‌اند و یک سهمیه‌ی ورود مشترک دارند.

**کلید دسترسی (رمز اول owner) از فرم پنل رد نمی‌شود.** Loomi هر فایل زیر `/data/secrets` را هم‌نام متغیرش می‌خواند، پس کلید روی خود volume است: `/data/secrets/Security__AccessKey`. آن را روی ماشین خودتان بسازید و نگه دارید، بعد از طریق stdin به سرور بفرستید تا در هیچ خط فرمانی دیده نشود:

```bash
openssl rand -hex 32 | tr -d '\r\n' > loomi-access-key
cat loomi-access-key | ssh <server> 'sudo docker run --rm -i --entrypoint sh -v harbora-vol-loomi-data:/data alpine -c "umask 077; mkdir -p /data/secrets && cat > /data/secrets/Security__AccessKey && chown -R 1654:1654 /data"'
```

این کلید فقط اولین owner را می‌سازد. بعد از اولین ورود (نام‌کاربری `owner`) رمز را از Settings عوض کنید؛ عوض‌کردن فایل بعد از آن اثری ندارد.

**هر به‌روزرسانی**، از ریشه‌ی مخزن:

```bash
harbora deploy loomi -y
```

`harbora.yml` فقط محتوای commit‌شده‌ی شاخه‌ی `master` را می‌فرستد؛ چیزی از `src/Loomi/Storage` (دیتابیس و نشست‌های ChatGPT اجرای محلی) هرگز بالا نمی‌رود. Harbora کانتینر تازه را کنار قبلی بالا می‌آورد و قبلی را بی‌خبر می‌کشد. Loomi تا وقتی نمونه‌ی قبلی قفلش را رها نکرده (حداکثر حدود ۲۰ ثانیه بعد از حذفش) نه مرورگری باز می‌کند نه صف را جلو می‌برد — در لاگ: «Waiting for the previous instance …» — و قفل Chromium به‌جامانده از کانتینر قبلی را خودش پاک می‌کند.

**نکته‌ها:**

- تغییر یک متغیر فقط با **Deploy** بعدی اعمال می‌شود، نه با Restart.
- `/dev/shm` روی Harbora ۶۴ مگ است و عوض نمی‌شود؛ Chromium با `--disable-dev-shm-usage` اجرا می‌شود.
- health check خود Harbora آدرس `/` را با نام کانتینر می‌زند و 400 می‌گیرد (به‌خاطر `AllowedHosts`)؛ عادی است و deploy را رد نمی‌کند.
- لاگ برنامه: پنل → Loomi → **Logs**.
- `deploy/backup.sh` مخصوص `docker compose` است و هنوز برای Harbora تطبیق داده نشده.

**هشدارهای تلگرام برای مالک.** Loomi وقتی حسابی دوباره ورود یا تأیید انسانی لازم دارد، سهمیه‌اش تمام شده یا به سقف روزانه رسیده، صف گیر کرده، یا سه ساخت پشت‌سرهم ناموفق شده، به تلگرام مالک پیام می‌دهد (یک بار، دوزبانه) و وقتی حساب برگشت هم خبر می‌دهد. برای روشن‌کردنش:

1. از [@BotFather](https://t.me/BotFather) یک ربات بسازید و توکنش را کپی کنید.
2. توکن را از clipboard مستقیم روی volume بنویسید (در هیچ فرم و چتی رد نمی‌شود):

   ```bash
   powershell -NoProfile -Command Get-Clipboard | tr -d '\r\n' | ssh <server> 'sudo docker run --rm -i --entrypoint sh -v harbora-vol-loomi-data:/data alpine -c "umask 077; cat > /data/secrets/Telegram__BotToken && chown 1654:1654 /data/secrets/Telegram__BotToken"'
   ```

3. در پنل Harbora روی Loomi **Restart** بزنید (فایل‌های `secrets` هنگام شروع خوانده می‌شوند، پس Restart کافی است).
4. در Loomi با owner: تنظیمات ← تلگرام ← کد بگیرید و در ربات بفرستید: `/start CODE`. هشدارها فقط به گفت‌وگوهایی می‌رود که به یک owner وصل‌اند.

## وقتی همه‌چیز ناگهان «Disconnected» می‌شود

معمولاً یعنی ظاهر صفحه‌ی ChatGPT عوض شده و selectorهای پیکربندی‌شده دیگر چیزی روی صفحه پیدا نمی‌کنند — نه یک باگ در Loomi. بدون rebuild قابل رفع است:

1. با owner وارد شوید، از Settings همان حساب → **Open secure browser** صفحه چت را باز کنید. با یک مرورگر معمولی خودتان (نه لزوماً همان noVNC) و DevTools همان صفحه را بررسی کنید و ببینید عنصر جدید composer/دکمه ورود/دکمه ارسال چه attribute تازه‌ای گرفته.
2. آن selector تازه را در `.env` به‌عنوان override بگذارید — بدون تغییر کد و بدون rebuild ایمیج:
   ```
   Browser__Selectors__Composer=selector-جدید-اینجا
   ```
   نام‌های قابل override: `Composer`، `LoggedIn`، `LoggedOut`، `Challenge`، `Send`، `Stop`، `Assistant` (جواب متنی مدل)، `ImagePending` (نشانه‌های «تصویر در راه است»)، `QuestionForm` و `QuestionInput` (فرمی که ChatGPT با آن قبل از ساختن سؤال می‌پرسد)، `GeneratedImage`، `FileInput`، `AttachmentMenu`، `UploadReady`، `UploadBusy`. توضیح نقش هرکدام کنار خودش در `src/Loomi/BrowserAutomation/BrowserOptions.cs` آمده.

   این کار فقط به این دلیل جواب می‌دهد که `docker-compose.yml` فایل `.env` را با `env_file` به کانتینر می‌دهد (Docker Compose نسخه‌ی ۲٫۲۴ یا جدیدتر). بدون آن، Compose از `.env` فقط برای `${...}`های خود فایل استفاده می‌کند و override بی‌صدا نادیده گرفته می‌شود.
3. ```bash
   docker compose up -d
   ```
   (بدون `--build`؛ فقط env عوض شده، کد همان است.)
4. Settings → همان حساب → **Check connection**. اگر Connected شد یعنی selector درست بود؛ اگر نه، مرحله ۱ را با selector دیگری تکرار کنید.

### جواب متنی، و انتقال خودکار به حساب دیگر

وقتی مدل به‌جای تصویر متن می‌دهد — مثلاً سؤالی درباره‌ی درخواست — کار با وضعیت **Answered** تمام می‌شود، متن به همان کاربر نشان داده می‌شود، اعتبارش برمی‌گردد و کاربر می‌تواند در همان گفت‌وگو جواب بدهد. حساب «تمام‌شده» علامت نمی‌خورد.

یعنی وقتی سهمیه‌ی تصویر یک حساب ChatGPT تمام شود و ChatGPT این را با متن بگوید، آن متن هم به‌صورت Answered به کاربر می‌رسد و کار خودکار به حساب دیگر نمی‌رود؛ چون Loomi از روی ظاهر صفحه نمی‌تواند «سهمیه تمام شد» را از «یک سؤال» جدا کند. اگر انتقال خودکار را می‌خواهید، عین عبارتی را که ChatGPT در آن حالت می‌نویسد در `.env` بگذارید:

```
Browser__SpentPhrases__0=image generation limit
```

جوابی که این عبارت را داشته باشد، مثل قبل حساب را برای امروز کنار می‌گذارد و کار را به حساب بعدی می‌دهد. بقیه‌ی جواب‌ها به کاربر برمی‌گردند. عبارت را خودتان از روی پیام واقعی بنویسید؛ حدس زدنش سؤال واقعی یک کاربر را بی‌صدا به گفت‌وگوی تازه‌ای در حساب دیگر می‌برد.

اگر به‌جای Disconnected، **VerificationRequired** می‌بینید، این selector خراب نیست — یک صفحه‌ی تأیید انسان‌بودن (معمولاً Cloudflare) است که فقط با ورود دستی در همان پنجره‌ی noVNC رفع می‌شود؛ Loomi هیچ‌وقت خودش تلاش نمی‌کند آن را دور بزند.
